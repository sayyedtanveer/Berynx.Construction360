# P1-M01 · Tenant, company and onboarding

## Review status

The module extends the Gate 0 projects. Runtime approval requires a .NET 10 build, a PostgreSQL migration rehearsal, integration tests and pilot UAT. Configure the identity and email provider before inviting a real administrator.

## Data and authority

| Resource | Ownership and behavior |
|---|---|
| Tenant | One versioned aggregate per tenant. Plan, enabled modules, lifecycle, cancellation instant and go-live instant belong to this record. |
| Setup configuration | Tenant-owned JSONB containing company, GST registrations, branch and plant identifiers, accounts, tax defaults, units, first admin and additional invitees, default roles, chart, wizard progress and imported master references. Child identifiers are resolved against the same aggregate. |
| Opening item | Composite tenant and item key, ledger category, optional bill reference and debit/credit in numeric(18,2). Customer and supplier items require bill references. A posted opening item is an allocation source for later receipt and supplier workflows. |
| Number assignment | Tenant, branch, document type, fiscal year, posting ID, sequence, rendered number, registration snapshot and posting time. Posting callers supply an active database transaction. Rollback releases the assignment. |
| Setup event | Append-only before/after data, actor, UTC instant and operation. Database triggers protect audit rows from ordinary updates and deletes. |
| Invitation | Transactionally queued per tenant and normalized email. The provider receives a stable delivery ID and tenant-specific role. Delivery status is persisted. |

Only a validated platform administrator can list or create tenants or change lifecycle. Onboarding uses the signed `tenant_id` and `sub` claims. Tenant-side access also checks the local Identity account and its active M02 membership; tenant-wide administration requires an unrestricted tenant role. Accountants can access the opening-balance endpoints. Tenant login, password setup, MFA and session issuance use the local ASP.NET Core Identity implementation. The configured HTTPS provider is retained only for invitation/password-reset email delivery; it does not authenticate users or issue tokens. First-admin activation uses a tenant- and delivery-bound, expiring protected invitation link to set the local Identity password.

| SCR-M01-01 tenant list | /setup/platform | GET /platform/tenants?page=1, POST /platform/tenants/{id}/status |
| SCR-M01-02 create tenant | /setup/create | POST /platform/tenants |

| SCR-M01-04 company | /setup/company | Step 1 |

| SCR-M01-07 opening balances | /setup/openings | GET and POST /openings, POST /openings/preview and /openings/excel |
| SCR-M01-08 checklist | /setup/checklist | GET /onboarding, POST /onboarding/go-live |
| SCR-M01-09 usage | /setup/usage | GET /onboarding/usage |
| Exit export | Tenant administrator | GET /onboarding/export returns a ZIP file |

Creation takes requestId (UUID), name, plan, adminEmail, modules and limits (users, storage in bytes, documents per month, messages). Step and opening commands take version and data. Lifecycle data contains status and reason. Go-live takes version. A stale update returns HTTP 409. A repeated successful go-live returns success. Previewing an Excel file uses the raw .xlsx request body. The first worksheet must have headers Kind, Ledger, Bill, Debit, Credit. Confirmation revalidates the rows before persistence. Opening edits after go-live require a later authorized adjustment posting.

Trial can become Active, Suspended or Cancelled. Active can become Suspended or Cancelled. Suspended can recover to Active or be Cancelled. Cancelled is terminal. The export window closes 30 days after cancellation. Data stays retained pending an approved retention and legal review. There is no scheduled purge.

## Deployment and rollback

Supply the database settings, `Jwt:Issuer`, `Jwt:Audience` and a random signing key of at least 32 UTF-8 bytes through secret configuration. Production must also set `DataProtection:KeyDirectory` to a durable, shared, access-controlled key-ring location. Configure `Onboarding:InvitationEndpoint` and `Onboarding:InvitationCredential` as an HTTPS email-delivery endpoint and bearer credential; it must deduplicate by `Idempotency-Key`, deliver the supplied activation URL and acknowledge durable acceptance. Password reset additionally uses `IdentityProvider:PasswordResetEndpoint`, `IdentityProvider:PasswordResetReturnUrl`, `IdentityProvider:ServiceCredential`, `IdentityProvider:InvitationEndpoint` and `IdentityProvider:InvitationReturnUrl`. These provider integrations deliver email only; they are not login or token authorities. Missing email credentials leave invitation delivery queued and password-reset responses remain generic. Configure approved tax defaults in `Onboarding:TaxDefaults` and optional document-specific pattern templates in `Onboarding:Numbering`. Tenant administrators review defaults before go-live.

From `backend/` with .NET 10, generate SQL for manual owner execution. The agent does not connect to or modify a database and does not run `dotnet ef database update`.

```powershell
dotnet tool restore
dotnet ef migrations script --idempotent --project src/Berynx.Infrastructure --startup-project src/Berynx.Api
dotnet test Berynx.Construction360.slnx
```

Migrations Onboarding and OnboardingDelivery add module tables, tenant-aware keys and lock/audit triggers. The complete manual deployment bundle is `database/scripts/P1-M01/`: execute `01-schema.sql`, `02-alter-existing.sql`, `03-indexes-constraints.sql`, `04-seed.sql`, then `05-verification.sql`; see its README. `99-rollback.sql` is a separate guarded owner action. The existing generated source remains `database/scripts/P1-M01-schema.sql`. The owner executes reviewed SQL and manages backups. The PostgreSQL test fixture requires BERYNX_TEST_POSTGRES pointing at a separate disposable localhost database whose name ends with _test. It creates and removes a uniquely named schema; when that configuration is absent, database-dependent tests remain pending.
