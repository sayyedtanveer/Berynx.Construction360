## M18 attachment boundary

M18 is implemented in source using a private filesystem provider outside the web root and a real ClamAV `clamd` adapter. Uploads are tenant/branch/trip/purpose-bound, size/type/signature checked, quarantined, malware scanned, encrypted after a clean verdict, and made reviewable only after persisted promotion. Authenticated preview/download and pending-scan recovery are branch scoped and audited. A scanner outage returns explicit 503 retry metadata and never treats an unscanned file as clean. Provider configuration and migration runbook: `docs/modules/P1-M18.md`.

M08 Verify remains fail-closed until clean evidence is returned by M18. M09 synchronizes only persisted reviewer decisions, and M10 revalidates persisted trip/challan facts. The local daemon and migration are not configured/applied in this run; full workflow acceptance still requires an authorized disposable PostgreSQL database and scanner-backed end-to-end test.
