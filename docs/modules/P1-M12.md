# P1-M12 Accounting — implementation checkpoint

**Status: PARTIAL.** Shared accounting/posting source and M10/M11 integrations exist; database-backed ledger reconciliation, remaining accounting workflows, and coverage requirements are still incomplete.

## Implemented

- Shared `IM12PostingEngine` and Infrastructure implementation for balanced, idempotent double-entry vouchers.
- Voucher + lines + immutable event creation occurs inside one serializable database transaction; period locks block posting.
- Ledger codes validate against the existing tenant `Setup.Ledgers` source. Manual journals are restricted to Journal/Contra and control-account group lines require a party.
- Branch and order/site/trip dimensions are retained on voucher lines. Trial-balance, voucher list, configured-account and period-lock API sources are added.
- Angular route `/m12/accounting` shows the live trial balance/voucher/account APIs and a manual journal workflow.
- Optional M12 module/permissions are seeded without granting tenant entitlements.

## Not covered

Reversals, period unlock/reason approval, P&L/balance sheet, full ledger/day/cash/bank books, opening balances, year-end close/carry-forward, Tally export, bank reconciliation, and margin reconciliation remain incomplete or unverified.
