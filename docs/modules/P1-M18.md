# P1-M18 secure evidence storage

**Source status: implemented; deployment acceptance remains pending.** M08 now uses a private, tenant/trip-bound document service and ClamAV `clamd` scanning. This is not a claim that a scanner is currently running, that the database migration has been applied, or that PostgreSQL end-to-end acceptance has passed.

## Providers and configuration

- **Local storage:** `FileSystemM18DocumentStorage` stores server-generated GUID keys outside `wwwroot`, encrypts clean content with ASP.NET Core Data Protection, holds uploads in a separate quarantine area, and applies owner-only Unix permissions or current-user/SYSTEM Windows ACLs. Storage rejects root paths inside the web root and symlink/reparse-point directories.
- **Scanner:** `ClamAvMalwareScanner` implements the ClamAV `clamd` `zINSTREAM` protocol. Only an explicit clean response promotes an upload. Infection marks the document rejected and deletes the quarantine object. Timeout, unavailable daemon, malformed response, or invalid configuration leaves it quarantined and returns HTTP 503 with retry metadata.
- **Cloud storage:** `IM18DocumentStorage` is the replacement seam for an organization-approved cloud adapter. No paid cloud service is required for local development; no cloud credentials or provider are included here.

Default local filesystem path: `%LOCALAPPDATA%\BerynxConstruction360\private-documents`. Optional environment configuration:

```powershell
$env:M18__Storage__RootPath = Join-Path $env:LOCALAPPDATA 'BerynxConstruction360\private-documents'
$env:M18__Documents__MaxFileBytes = '10485760'
$env:M18__Scanner__Provider = 'ClamAV'
$env:M18__Scanner__Host = '127.0.0.1'
$env:M18__Scanner__Port = '3310'
$env:M18__Scanner__TimeoutSeconds = '45'
```

A `clamd` service must be provided by the operator. For a local Docker-based setup, use an approved ClamAV image and bind port 3310 to loopback only; do not expose the scanner daemon to an untrusted network. The application does not install or start system software. Production must configure a durable, access-controlled Data Protection key ring and its approved key-encryption mechanism, and must replace local filesystem storage with the approved cloud adapter where required.

## API and lifecycle

1. Authenticated M08 trip-update users upload JPEG/PNG/WebP signature images or JPEG/PNG/WebP/PDF photo evidence (10 MB maximum, also bounded by tenant storage/document quotas).
2. The API verifies MIME allowlist and file signature, stores the stream under a generated identifier in quarantine, persists tenant/branch/trip/purpose/version metadata and upload audit event, then scans it.
3. A clean scan encrypts and atomically promotes the object. Only then is the ID added to the trip's signature/photo reference and the old version marked non-current. Previous versions and audit records remain; a delayed clean scan for an older pending version cannot replace a newer upload as current.
4. A pending scan can be retried with `POST /api/v1/m08/trips/{tripId}/evidence-assets/{documentId}/scan-retry`; pending scan IDs can be restored after page reload using the branch-authorized pending-scan endpoint.
5. M08 Verify requires current clean scanned evidence. Preview/download routes require M08 evidence-review permission and trip branch access; both audit access. Verify/Reject persists reviewer, timestamp/reason and document review events. No OTP, SMS, or auto-verification is used.
6. The existing M09 synchronization and M10 persisted-fact/snapshot checks remain fail-closed until a supervisor verifies the clean evidence.
